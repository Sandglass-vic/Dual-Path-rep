# pza100：g5/g6 A100 环境

> 返回 [文档索引](README.md)

本分支用于将 DualPath 从原 GAIA DGX H100 环境迁移到 g5/g6 A100 集群。GAIA
Job、Lustre 带宽和 H100 拓扑数据作为历史基线保留；除非明确标注，不能直接用于
pza100。

## 路径

```bash
export CODE_HOME=/data/home/yongxiao/dual-path
export RUNTIME_HOME=/data/home/yongxiao/mydata
export IMAGE_DIR=$RUNTIME_HOME/images
```

g5 的 `/data` 是本地盘，g6 通过 IPoIB NFS 挂载同一目录。代码、镜像、模型和
运行结果因此在两节点可见，但其存储语义和带宽不等同于 GAIA Lustre。

2026-09-17 实测文件系统：

```text
g5 /data: /dev/nvme2n1, XFS, 4 KiB filesystem block
g6 /data: 192.168.10.5:/data, NFSv4.1 over ibs3,
          rsize=1 MiB, wsize=1 MiB, hard, local_lock=none
```

实测的带宽、延迟分布和理论上限见 [io-test/RESULTS.md](../io-test/RESULTS.md)
的 pza100 章节（Job 431 / 442 / 446）。要点：g5 本地冷读 6.43 GiB/s（打满 NVMe），
g6 经 NFS 最好只有 3.47 GiB/s = 29.8 Gb/s，即 800 Gb/s 存储网卡的 3.7%，且加并发
无效——瓶颈是 `nconnect=1` 的单条 TCP 连接加上 IPoIB datagram MTU 2044。

因此当前 HiCache L3 是 SGLang POSIX `file` backend，物理拓扑为“g5 本地 XFS、
g6 NFS client”，不是 Lustre。历史日志和 patched SGLang 中的 `lustre_*` timing
字段名暂时保留兼容性，但在 pza100 上只表示通用文件读取时间，不能解释为 Lustre
带宽。`DUAL_PATH_O_DIRECT_READ` 默认关闭；启用时启动脚本会在实际 cache 目录执行
对齐的 O_DIRECT read probe，因此 XFS、NFS 和历史 Lustre 均按当前内核与挂载的
真实能力决定是否可用。`lfs getstripe`、OST stripe 和 LNet rail 等 GAIA 设置
不适用于 pza100。

## Slurm 与硬件

| 项目 | pza100 配置 |
|---|---|
| 集群 | `g5g6` |
| 节点 | `g5`, `g6` |
| 日常分区 | `run`，最长 4 小时 |
| 构建分区 | `build`，最长 12 小时 |
| GPU | 每节点 4 × NVIDIA A100 PCIe 40GB |
| CPU/内存 | 每节点 2 × EPYC 9654，约 502 GiB |
| Enroot | 4.2.0 |
| PD HCA | `mlx5_0`, `mlx5_4` |
| Socket/Gloo 接口 | `ibs3` |

GPU 作业至少显式设置：

```bash
#SBATCH --gres=gpu:4
#SBATCH --mem=0
#SBATCH --cpus-per-task=192

export NCCL_IB_HCA=mlx5_0,mlx5_4
export NCCL_NET_GDR_LEVEL=PIX
export NCCL_SOCKET_IFNAME=ibs3
export GLOO_SOCKET_IFNAME=ibs3
```

GPU0/1 与 `mlx5_0` 邻近，GPU2/3 与 `mlx5_4` 邻近。四卡进程的建议 Mooncake
映射为：

```json
{"0":"mlx5_0","1":"mlx5_0","2":"mlx5_4","3":"mlx5_4"}
```

该映射已由 2026-09-17 的 pza100 1P1D TP4 多节点 smoke 验证。

## 当前运行入口

`scripts/pd_alloc.sh` / `scripts/pd_benchmark.sh` 已迁移为以下默认值：

- 1P1D、每个 engine TP4 / 4 GPU；
- Router/replay client 与最后一个 Decode 节点共置；
- `run` 分区、每节点 192 CPU、全部节点内存；TP4 默认每个 rank 使用 48 个
  OMP/MKL threads；
- 默认 patched 镜像为
  `sglang:26.01-py3-mooncake0.3.13.post1-dualpath-patched.sqsh`；
- runtime/model/result 根目录为 `/data/home/yongxiao/mydata`；
- Mooncake rank 映射为 GPU0/1→`mlx5_0`、GPU2/3→`mlx5_4`；
- 调试默认 context length 为 4096。

allocation 配置只保存节点角色、资源、TP size、共享路径和默认镜像。实验参数不写入
allocation env；启动 Prefill、Decode 和 client 时分别指定，并且三端需要保持一致。
这包括 `DUALPATH_L3_READ_PATH`、`DUAL_PATH_O_DIRECT_READ`、`ABLATION_PROFILE`、
context length、HiCache/Host staging 和 timing 参数。`TP_SIZE` 默认固定为 4，
与 allocation 的 GPU 资源一起保存，不能在单个角色启动时覆盖。显式运行参数在
加载 allocation env 后仍具有最高优先级。

当前仍有以下限制：

- 1P2D、2P2D 无法在本集群复现；
- H100 80GB 上的 KV、HiCache 和 Host staging 参数不能直接沿用到 A100 40GB。

脚本迁移、静态检查和双节点 1P1D TP4 GPU/RDMA smoke 已完成。Job `440` 的 Decode
O_DIRECT wall time 为 20.14 秒；Job `441` 的 Prefill O_DIRECT wall time 为 20.77 秒，
与修复前已成功的同配置 20.75 秒一致，未观察到明显性能回退。GAIA 历史结果仍以
原路径、Job ID 和 TP8 参数记录，避免伪造迁移后的复现结果。
